**任何 step 执行失败时，禁止直接终止！必须先释放已申请的算力资源：**

| 失败位置 | 兜底动作 |

| step_7 失败 | **必须先执行 step_9 释放 GPU 实例**，再终止 |
| step_8 失败 | **必须先执行 step_9 释放 GPU 实例**，再终止 |
| step_9 失败 | 记录告警，提醒用户手动到平台释放 GPU 实例 |

## 📁 【平台目录规范】

Lab4AI 实例上的项目目录结构为：

```
/workspace/user-data/codelab/{repo_name}/
├── code/              ← GitHub 代码（git clone 到此）
│   ├── data -> ../data    ← 软链接，项目代码可直接引用
│   └── model -> ../model  ← 软链接，项目代码可直接引用
├── data/              ← 数据集存放
└── model/             ← 模型权重存放
```

- 代码、数据、权重**严格分离**
- `code/` 内的软链接保证项目代码中 `./data/` 和 `./model/` 的相对路径引用不受影响
- Conda 环境路径：`/workspace/envs/{repo_name}`
- PyTorch 统一使用 **CUDA 12.1**（`--index-url .../cu121`），Lab4AI H100 实战验证兼容性最佳
